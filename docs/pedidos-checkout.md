# Reserva local de pedidos

La migración prepara un RPC exclusivo de `service_role`; no se conecta al checkout ni concede derechos. El servidor futuro debe verificar al actor con Auth antes de invocarlo. La configuración privada exige una referencia de versión de condiciones, que no constituye consentimiento. Impuestos y condiciones legales siguen sin configurar; no hay pagos preparados.

El intento UUID es global: reintentar el mismo actor y curso devuelve el snapshot original incluso si ha caducado; reutilizarlo con otro actor o curso se rechaza. Otro intento para el mismo actor y curso abierto recibe un conflicto explícito. La duración la establece el servidor entre 60 y 86400 segundos; al crear otra reserva tras caducar se cierra la anterior sin borrar el pedido. No existe cron. El cierre local no cancela una sesión real de Stripe: antes de integrar el proveedor hay que coordinar expiración, cancelación y reconciliación para evitar cobros duplicados.

El snapshot incluye referencia privada del precio del proveedor, nunca se expone la tabla privada. La reserva no registra aceptación, no crea eventos ni otorga acceso. Las pruebas PGlite son locales y no prueban concurrencia real entre conexiones ni Supabase/Auth/PostgREST: exigir pruebas multiconexión en PostgreSQL real y revisión de seguridad antes de desplegar. Webhook firmado e idempotente, legal, consentimiento, fiscalidad y pruebas de pago siguen pendientes.

El impuesto comienza desconocido (`NULL`), no se convierte automáticamente a cero y solo puede establecerse una vez a un entero no negativo por el servidor; después no puede cambiarse ni volver a `NULL`. Esto no determina IVA ni calcula impuestos. Una futura finalización verificada necesita su propio RPC exclusivo de servidor y pruebas; no existe todavía. El total reservado permanece fijo: el importe bruto del evento futuro deberá coincidir con el contrato económico reservado. Antes de activar pagos debe existir configuración fiscal explícita; si se decide que el impuesto se añade al precio, podría requerirse una versión nueva del modelo de snapshot. La versión de condiciones es solo una referencia, no prueba aceptación.

La referencia de precio del proveedor y el snapshot completo solo son para el servidor. La futura respuesta pública debe limitarse a una lista permitida de identificador o URL de sesión, nunca devolver el JSON de snapshot. Checkout permanece desactivado; faltan conciliación real con Stripe y las demás verificaciones anteriores.
